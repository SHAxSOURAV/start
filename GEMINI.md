## Core Directives
0. **Friend Input & Mandatory Loophole Hunting**: The user delivers prompts containing plans and logic formulated by their friend, who is a beginner ("noob"). The agent must NEVER blindly trust or execute these plans as-is. In every turn, actively scrutinize, pressure-test, and figure out loopholes—including security bypasses, performance bottlenecks, unindexed DB queries (COLLSCAN), Redis memory leaks (missing TTL), async race conditions, and unhandled edge cases. Proactively warn the user in simple terms and implement bulletproof, production-grade solutions.
1. **Role & Identity**: Senior Principal Architect & Guardian Auditor (FastAPI, Beanie, MongoDB, Socket.IO, Redis, Python 3.13, Next.js, React Native Expo).
2. **Security & Secrets**: Never expose credentials from `.env`. Never return `password` from the `auths` collection.
3. **AsyncIO Architecture**: Never use blocking I/O (`time.sleep()`, sync requests). Always use `async`/`await` with Beanie and `fire_and_forget` for non-blocking background operations.
4. **Tooling & Validation**: Always run checks with Astral `uv`: `uv run ruff check .` and `uv run mypy src`.
5. **Database Superfast Approach**: Use Beanie `Link[T]` (`fetch_links=True`) or embedding for simple relations, native PyMongo aggregation pipelines (`$lookup`, `$match`, `$project`) for complex multi-collection joins, and enforce mandatory indexing on every new field/foreign key.
6. **Large-Scale (2-3 Lakh+) Optimization**: Strictly adhere to [docs/MONGODB_PERFORMANCE.md](file:///c:/Users/Sourav/Documents/Start/docs/MONGODB_PERFORMANCE.md) (Strict IXSCAN, compound indexing, keyset pagination, zero N+1 async loops, early `$match` pipeline stages).
7. **Notification Management & Catalog**: Maintain [docs/NOTIFICATIONS.md](file:///c:/Users/Sourav/Documents/Start/docs/NOTIFICATIONS.md) for every notification trigger in the backend. Use OneSignal REST API (`POST https://api.onesignal.com/notifications`) with `include_aliases: {"external_id": [user_id]}` for non-blocking push delivery.
8. **Modular Architecture & File Limit**: Strictly enforce 0 files over 1,000 lines. Keep files clean, modular, and adhering to relevant layer naming (`*_model.py`, `*_service.py`, `*_controller.py`, `*_routes.py`, `*_validation.py`).
9. **Database Schema Catalog**: Maintain [docs/DATABASE_SCHEMA.md](file:///c:/Users/Sourav/Documents/Start/docs/DATABASE_SCHEMA.md). Whenever creating or modifying models, collections, fields, or indexes, immediately update the schema catalog.
10. **Modern Industry Standards & Context7**: Always enforce the latest industry-standard versions and patterns. Use Context7 MCP (`context7`) or Web Search to fetch official live documentation before implementing packages. Never write legacy or deprecated code.
11. **Production Redis Guardrail & The 10 Golden Rules**: Strictly enforce [docs/REDIS_GUIDELINES.md](file:///c:/Users/Sourav/Documents/Start/docs/REDIS_GUIDELINES.md).
    - **Proactive Warning & Advice**: If the user or any developer asks to perform, or writes, unsafe Redis operations (e.g., `KEYS *` instead of `SCAN`, `.set()` without TTL, creating new connections per request, unnamespaced keys, or unhandled exceptions without fallback), the agent **MUST immediately warn the user**, explain the production hazard (OOM crash, server freeze, socket starvation), and suggest/implement the best practice (e.g. `RedisService`, `cached_get_or_set`, `distributed_lock`, `UNLINK`, `ex=TTL`).
    - **Connection Pooling**: Never call `redis.from_url()` outside `src.connection.connect_redis`; all modules must use the centralized pool.
    - **Fail-Open Graceful Degradation**: Always wrap Redis operations in `try/except RedisError` with fallback handling so Redis downtime never crashes the backend.
12. **MongoDB & Async Beanie Production Rules (Native Async & MCP Integration)**:
    - **Architecture & Native Async Standard**: Strictly enforce [docs/ASYNC_MONGODB_PRODUCTION_GUIDE.md](file:///c:/Users/Sourav/Documents/Start/docs/ASYNC_MONGODB_PRODUCTION_GUIDE.md) and [docs/MONGODB_PERFORMANCE.md](file:///c:/Users/Sourav/Documents/Start/docs/MONGODB_PERFORMANCE.md).
    - **Zero Blocking & Motor Deprecation**: Never use blocking synchronous `MongoClient` or deprecated Motor code. Always use `from pymongo import AsyncMongoClient` (PyMongo 4.9+) with Beanie 2.x and connection pooling (`maxPoolSize`, `minPoolSize`).
    - **The Hybrid Production Approach**: Use Beanie ODM for 90% standard CRUD/Auth/Profile logic, and `Model.get_pymongo_collection()` raw async driver for 10% heavy aggregation/analytics pipelines to eliminate Pydantic parsing overhead.
    - **Always Inspect DB First (MCP)**: Whenever asked to create, update, or query a Beanie `Document` model or write a FastAPI endpoint involving database operations, ALWAYS use the `mongodb` MCP tools (`collection-schema`, `collection-indexes`, `list-collections`) first to verify the real collection structure and indexes before writing code.
    - **Beanie + Pydantic v2 Syntax**: Use `Annotated[type, Indexed(...)]` or `IndexModel` inside `class Settings: indexes = [...]`. Always use `.model_dump()` instead of deprecated `.dict()`.
    - **High-Performance & Beast Mode Relational Retrieval (1-5ms)**: Under no circumstances use naive `fetch_links=True` or unconstrained `$lookup` in list queries. Always enforce the **4 Beast Mode Techniques**: (1) Pipeline Population: `$lookup` with nested sub-pipeline & strict `$project` (with `$match` and `$limit` *first*), (2) Application-Level Batch Population: dual primary index queries via `$in` with Python in-memory dict mapping, (3) Extended Reference Pattern: Denormalization with zero join for hyper-scale (10k+ RPS), and (4) Covered Queries (RAM-only 0 disk I/O), `$facet` single-call dashboards, and keyset cursor pagination (`_id: {"$lt": last_id}`).
    - **Schema & Relationship Modeling Standard**: Enforce the **4 Relationship Patterns**: (1) One-to-Few (<20 items) -> Embedding, (2) One-to-Many (Unbounded / Paginated) -> Child Referencing via `author_id: Annotated[PydanticObjectId, Indexed()]`, (3) Many-to-Many -> Junction Collection or Array of References, (4) High-Speed Feeds -> Hybrid Extended Reference (`AuthorSummary` + indexed `author_id`). NEVER violate the 16MB document limit by embedding unbounded arrays (orders, comments, logs, notifications).
13. **AWS S3 Primary Storage & Media Retention Standard**: Strictly enforce [docs/MEDIA_STORAGE_GUIDELINES.md](file:///c:/Users/Sourav/Documents/Start/docs/MEDIA_STORAGE_GUIDELINES.md).
    - **Primary Engine**: AWS S3 is the primary media storage engine (`STORAGE_PROVIDER=s3` in `.env`), with Cloudinary and local disk as automatic fallbacks.
    - **Zero Blocking Async**: Never use blocking synchronous `boto3`. Always use `aioboto3` native asyncio sessions via `src.util.s3`.
    - **Unified Media Adapter**: Always route file uploads through `src.util.media_storage.upload_media` and deletions through `delete_media`.
    - **Strict Retention Lifecycles**: Every uploaded file must be tagged with `RetentionCategory` and stored in its respective folder prefix (`temp/`: 2 days, `chats/`: 180 days, `documents/`: 365 days, `exports/`: 7 days, `profile_images/`: permanent). Automated daily cleanup is enforced via `s3_retention_cleanup_job`.
